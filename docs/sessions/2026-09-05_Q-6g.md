# Session · 5 September 2026 · Q-6g, prose is not a treatment

Queue item Q-6g under the standing authorization. **No migration**, as the row
expected.

## What the row asked for, and the shape it forbade

A table whose erasure treatment exists ONLY as prose, and nowhere as an
executed statement, must fail `erasure-coverage`. The row is explicit about the
shape this must NOT take: **it cannot demand a particular SQL shape**, so it
detects the ABSENCE OF ANY statement touching the table rather than the
presence of a specific one. Demanding a shape would fail on every legitimate
no-op treatment and be allowlisted into silence, which is the failure mode
CLAUDE.md already names as the reason the per-column producer rule cannot
become a guard.

## What was built

A second test in `packages/schema/src/erasure-coverage.test.ts`. The tool's
source is stripped of comments and each household-referencing table must appear
in what is left, whatever it is doing there. **The first test is untouched**:
its floor is still being NAMED, per the 4 September ruling, and a comment
satisfies that half exactly as a query does. The two tests answer two
questions, and their allowlists are deliberately SEPARATE so a reason for one
cannot excuse the other.

The strip is conservative about strings: `//` inside a quoted literal is not a
comment, because a SQL string mentioning a table is code. Being wrong in that
direction would invent failures; being wrong the other way only leaves this
test as weak as the one above it.

## Proven, and the red proof is the finding's own instance

- **RED on the real Q-6-1 case.** Removing the executable
  `UPDATE decision_right ...` and leaving the header prose left the FIRST test
  green (three prose mentions still name the table) and turned the new one RED
  naming `decision_right`. That is exactly the hole the finding was filed for,
  reproduced and now caught.
- **GREEN on a deliberate no-op recorded as code.** The same statement replaced
  by `const DELIBERATELY_UNTOUCHED = ["decision_right"]` passes, which is the
  acceptance criterion's second clause: a treatment of ANY shape counts.
- **The precondition refuses rather than passing vacuously.** With the strip
  disabled the test fails on its own precondition (`37616 to 37616`) instead of
  passing over the whole file. A proof asserts its own preconditions.
- Both mutations were confirmed landed before the result was read.

## The audit clause

**45 household-referencing tables were audited for the prose-only shape and
none was found.** The guard IS the audit, and it runs on every CI run rather
than being a survey somebody did once. The count is computed at test time with
a floor, so a broken census fails instead of reporting a clean zero.
