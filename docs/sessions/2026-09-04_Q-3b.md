# Session Q-3b · 4 September 2026 · the domain-event catalog completion (0063)

Queue row: Q-3b of the re-cut `docs/BUILD_QUEUE.md`, authorized by the
founder after Q-2's acceptance. Authority: RFC-ATTR-01 Amendment 1
§A1.3 (Ruling 2 §4): the domain-event catalog item was PARTLY provided
by 0046 (the s4 envelope carries event_version, correlation_id,
object_id, actor, sensitivity, provenance); the remainder is
`causation_id` and the family catalog. One migration (0063).
Acceptance, verbatim from the row: given any emitted event caused by
another, when written, then it carries `causation_id`; given a
family-catalog kind, when emitted, then the drain consumes it as a
registered kind.

## Plan (written before building)

**Read first (done, three parallel readers):** the emit path
(`emitOutboxEvent` in packages/schema/src/events.ts, the one way in;
all 26 production call sites and every kind string), the drain and
registry (run.ts: `OUTBOX_CONSUMERS` keyed by kind string,
`registeredKinds = Object.keys(consumers)`, the A2 batch WHERE, the
metric upsert; tests register consumers via the `opts.consumers`
override), and the schema precedent (event_outbox has NO
(household_id, id) unique index today; the 0056 situation pattern is
uniqueIndex target plus `foreignKey({...})` referencing side, with the
CREATE UNIQUE INDEX preceding the FK in SQL, which is the 0058
ordering lesson).

**1. Migration 0063** (idx 63, the session's one): on `event_outbox`,
ADD COLUMN `causation_id` uuid (nullable: most events have no cause,
and legacy rows never will); CREATE UNIQUE INDEX
`event_outbox_household_id_key` on (household_id, id) (no data
precondition: id is the primary key, so the pair is already unique);
then the SELF-REFERENTIAL composite FK
(household_id, causation_id) referencing (household_id, id), the 0056
situation pattern turned inward, so a cross-tenant causation link is
UNREPRESENTABLE rather than merely unlikely. Generated SQL is READ and
reordered by hand if drizzle-kit emits the FK before the index (0058's
exact failure). Erasure needs no treatment change: the one
`DELETE FROM event_outbox WHERE household_id=$1` removes parent and
child together, and FK enforcement is end-of-statement, proven in SQL
below rather than assumed; the tool's event_outbox header bullet gains
one line saying so.

**2. `emitOutboxEvent`** gains optional `causationId?: string | null`,
stored as `causation_id`. PRODUCER, stated per the G-85 rule: the
COLUMN's mechanism ships with its plumbing and its tests now, and NO
PRODUCTION SITE passes a non-null value yet; the first real producers
are the Q-12b reconciliation consumers (an expected_event opened by a
sweep is caused by the event whose absence it noticed). Deliberate
schema-ahead-of-writer, written down at the only moment the answer is
known.

**3. The family catalog** `packages/schema/src/event-catalog.ts`: the
ELEVEN families from the withdrawn RFC-001 §3a adopted VERBATIM
(capture, knowledge, expectation, source, commitment, changeset, work,
decision, vendor, ai, delight), the estimate-hierarchy
verbatim-adoption pattern, no invention. Exports the readonly list,
`catalogFamilyOf(kind)` (the family when the kind is
`<family>.<rest>`, null otherwise), and `isCatalogKind(kind)`.
`delight.*` is included because dropping a name would be editing the
adopted list; the Delight EPIC stays held post-E4 (the benchmark
record), and the comment says a reserved name is not a build. The
catalog is a forward namespace: the LIVE s4 kinds (`work_item.*`,
`decision_record.*`, `visit.*`, `field.changed`, ...) are deliberately
OUTSIDE it and stay legal; renaming shipped kinds would be a
shipped-semantics change nobody ruled (ground truth below).

**4. Proofs, red first:**
- SQL refusals on the real database: a causation_id naming an event in
  ANOTHER household refused by the composite FK; a causation_id naming
  no event refused; same-household causation accepted; null accepted;
  and the erasure shape accepted (parent and child deleted in the one
  household-keyed statement).
- Drain integration (the acceptance's second clause): emit a
  family-catalog kind with a causation chain to a prior event, register
  a consumer for it through the standing `opts.consumers` override,
  drain, and read the consumed row back by SELECT with its causation
  intact (the G-72 rule). Emitting through `emitOutboxEvent` proves the
  plumbing end to end.
- Catalog unit tests: the eleven families exactly, family resolution on
  a catalog kind, null on every LIVE legacy kind (enumerated from the
  emit map), and the two helpers agreeing.
- The red direction for the FK proofs is the SQL refusal itself; the
  red direction for the plumbing is asserting the column absent before
  0063 applies locally is not meaningful (the migration IS the change),
  so the mutation-landed check is the SELECT-back of a written
  causation value.
