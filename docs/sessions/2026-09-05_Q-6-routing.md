# Session log: Q-6's four routing proofs

**Queue row:** Q-6, the routing clause moved onto it from Q-5 by founder ruling
4 September 2026 and instructed built 5 September once `candidate_routing` and
`decision_right` both existed. **Migration:** none.

## What was missing, stated precisely, because it is not what it looks like

`routeByDecisionRights` has had seven unit tests since Q-6-2 and every one of
them passed an ARRAY THE TEST BUILT. **The function had never once been run
against a `decision_right` row that was really in the database.** That is the
standing rule about a gate whose input comes from outside the process: a
sentinel proves the logic and says nothing about the input.

So the gap was not the routing logic and not the vocabulary. It was that
nothing read a household's own rights and acted on them.

## What was built

`packages/trigger-engine/src/prompt-routing.ts`: `routePromptItem` reads the
household's rights from the database, routes, stamps `decide` where the answer
is to ask, and logs every decision either way.

## The four directions, in the founder's order

The null-threshold case first, because it is the state a household is in before
anyone configures anything, and the safe answer has to be the one a MISSING ROW
falls into rather than an exception somebody wrote.

| # | Direction | Real input | Result |
|---|---|---|---|
| 1 | no right on record | zero rows, asserted as a precondition before the case runs | proposes, stamps `decide` |
| 2 | a right recorded in WORDS | a real `approved_substitute_only` row | proposes, stamps `decide` |
| 3 | at or below a real ceiling | a real 15000-cent ceiling, amount 15000 | permits acting, stamps nothing |
| 4 | one cent above the same ceiling | the same row, amount 15001 | proposes, stamps `decide` |

Every case reads the stage back **from Postgres** rather than from the
function's return value, and a fifth test proves all four were logged,
including the one that acted without asking.

## Two things reported rather than resolved

**Only `decide` is stamped.** The acceptance clause names that value for the
proposing side and there is none for the other: the Four-Stage spec's own flow
sentence names FIVE movements (anticipation, identification, decision-routing,
**execution**, monitoring) against the four-value tag it specifies two
paragraphs later, with `execution` absent. That contradiction was reported when
Q-5 shipped the tag and is still unresolved. It is not fixed here by inventing
a fifth value or by borrowing `monitor`, which means something else.

**Nothing executes.** `auto_execute` is a statement that the household's rights
PERMIT acting without asking. No execution engine exists in this tree, so the
outcome is recorded and logged and no act follows it. Stated because the word
reads like something happened, and a later reader counting auto-executions
would otherwise be counting permissions.
