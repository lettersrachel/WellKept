# Session log: Q-11q, the self-contradicting queue row

**Queue row:** Q-11q, in queue order after Q-11l. **Spec:** G-133, filed
5 September 2026 while working Q-10 in queue order. **Migration:** none.

## The plan, written before building

**What the row asks for.** Q-10's prerequisite cell read
`WK-STD-028 (not in repository)` while its status cell read `**NEW.**`,
three cells apart on one line, and had done since the 3 September re-cut.
Every other check in this repository compares one artefact against
another; nothing compares a queue row against itself.

**The detection is a same-row comparison rather than a judgment.** Where
a row's Spec cell names an input as ABSENT, the row must say what it does
about that. Both halves of the vocabulary are taken from the file's own
existing text rather than invented, which is what keeps this a
consistency check and not a new taxonomy.

**Files to be touched, read first:**

- `docs/BUILD_QUEUE.md` (the subject; 57 `Q-` rows, six columns)
- `packages/schema/src/queue-row-consistency.test.ts` (new guard)
- `packages/schema/src/guards-manifest.test.ts` (the guard set)
- `CLAUDE.md` (the guard table; a guard added without a row fails CI)

**The three-clause rule, each clause with its reason:**

1. **The status opener carries a marker.** Every row states its status in
   the first bolded run of the Standing cell. If that opener says the row
   is closed, delivered, deferred, founder-side, corrected, blocked,
   gated or split, the absence is dispositioned by the status itself.
2. **The Standing cell names the absent input.** If the status text names
   the document by name, somebody has thought about it there. This is the
   clause that lets Q-17 pass: its opener reads `PARTLY` and its body
   says `WK-TRN-007 does not exist`.
3. **The Spec cell carries a disposition after the absence.** Q-1 and
   Q-13 both say `row ran on its acceptance` in the prerequisite cell
   itself, which is the disposition living where the absence is stated.

**What the guard cannot do, and the limit belongs on the row.** It reads
PROSE, so it catches a STATED contradiction and nothing else. A row can
be wrong in ways no same-row comparison can see: a prerequisite that is
absent and not SAID to be absent is invisible to it, and a disposition
that names the right document for the wrong reason reads as a pass.
`(bundle)` is deliberately not read as an absence phrasing, because it
names a document's origin rather than asserting it is missing.

**Predicted red on today's tree, written before the run so the run can
contradict it:** Q-7, Q-12, Q-14 and Q-16. Each will be corrected under
the standing queue-row-correction authority with the evidence recorded
and the original claim left visible, never deleted.

## What the run found, and the prediction it contradicted

**The pre-run prediction above was WRONG about Q-16**, and the reason is the
class the guard exists for. Two rows carried an unescaped `|` and parsed into
seven cells. Q-8b's was inside the code span `--scope corporate|member`. Q-16's
was mine: the 5 September item 9 note had been inserted as a spurious extra
CELL, shifting every column after it, so my census read the note as the status
and never saw `Gated in part on the WK-TRN-009 document existing`. **A
cell-indexed read of a mis-split row returns a confident answer about a
different cell.** Both rows fixed; the parser now splits on unescaped pipes
only.

**Three rows genuinely contradicted themselves** and are corrected under the
standing queue-row authority, each keeping its original claim visible:

- **Q-7**, `PARTLY.` beside an absent A129. **This row was reported blocked
  when it came up in queue order earlier the same day, and the report never
  reached the row**, which is the G-133 shape committed by the session that
  filed G-133.
- **Q-12**, `NEW` beside an absent Inference Cascade Spec. Year-two, and the
  tier is not a defence: Q-10 shows the cost arrives when somebody finally
  picks the row up.
- **Q-14**, `PARTLY.` beside two absent specs. One is partly recovered: the
  adopted Workload Forecasting brief summarises `WK Task Stacking & Errand
  Optimization` in a single line, which sizes the row without unblocking it.

**And G-134, found while wiring the guard's own CLAUDE.md row.** The manifest's
table check carried a second hand-written list of guard names, so adding a
guard to the file list never required a table row; deleting the fresh row left
the manifest green. Fixed by deriving the names from `GUARD_FILES`, proven red
and green.
