Queue item Q-11k under the standing authorization. **No migration.**

## What the row asked for, and why it was built differently

The row says: extend the D7 guard's walked set to the member-scope archive
path. **That would not have worked, and finding out why is the substance of
this session.**

`clientSurfaceFiles()` walks the `(client)` route group plus three named copy
builders, and the test scans each file's SOURCE for duration IDENTIFIERS. The
archive's risk is different in kind: admitting a duration-carrying table to
`MEMBER_SCOPE` means writing that table's NAME into a list. **No duration
identifier appears anywhere in that edit.** A file-level text scan would have
read `household-archive.ts`, found nothing, and passed while the member archive
shipped every visit's hours.

So the check is a **computed set comparison** rather than a text scan: the
tables carrying a duration-typed column, intersected with the member scope, must
be empty. Both sides are derived from the schema and the archive module, so a
duration column added to a member-scope table tomorrow fails here without
anyone remembering this rule.

## Proven

- **RED on the real leak shape**: `estimate_snapshot` planted into

- **RED on a broken detection**: with the duration regex disabled the test
  refuses on its own precondition ("no duration-carrying table found at all")
  rather than passing over an empty set.
- **GREEN restored**, and green on the tree as it stands.

## The first red proof did not go red, and that is the useful part

It planted `visit_command`, and the check correctly stayed GREEN. `visit_command`
carries the hours the HOM typed **inside its jsonb payload** and has no
duration-typed column, so the author had picked the one table the header
documents as invisible to this check.

**That confirms the documented limit is real rather than theoretical**, and it
is exactly the freeze packet's item A shape (b): admitting `visit_command` under
a projection that drops duration KEYS is a live option in that ruling, and its
dropped-key list is a written, reviewed list precisely because no schema-derived
check can read inside a payload. Recorded rather than tidied away, because a red
proof that stays green is either a broken guard or a misunderstood one, and
telling those apart is the whole reason the result gets read.
